Chapter 3

Projects & tasks

The everyday work: creating projects with full metadata, building the task tree, editing tasks in the two-pane editor, and finding, filtering and changing many tasks at once.

Projects

Create a project

  1. Open Projects and choose New project (or press Ctrl + K and type “new project”).
  2. Pick a template to copy its task tree and taxonomy presets, or start blank (7.3).
  3. Fill the editor. The left pane holds the name and description, the right rail status, priority, topics, work types, members and tags; the Timeline and Budget & risk tabs hold dates and money.
  4. Create. You are the owner and an admin; members you picked join as editors (change roles later, 3.3).

Projects

Members and roles

In Project Settings (or from a sketch's Share dialog), project admins pick an existing user and a role: viewer, editor or admin. The owner always stays admin; roles change instantly. See 2.4 for what each role may do.

Tasks

Create and edit tasks

Use Add task on the project page, c anywhere, or the + on a task row to add a child. Clicking a task opens the two-pane editor: content on the left, the properties rail on the right, tabs for schedule, budget and risk, checklist, time, files and comments.

Finding work

Filters, saved views, search and shortcuts

Filter bar

The project task list, the project board and My tasks share one filter bar: text, status, priority and assignee (including “Unassigned”). Parents stay visible when a child matches. Sort (manual, due date, priority, status, title, created) and group (status, priority, assignee) apply to lists.

The state lives in the URL (?q=api&status=Todo,In%20Progress&sort=due&group=assignee), so a link shows exactly what you see. Views › Save current view… keeps named views in this browser.

Command palette

Ctrl/⌘ + K opens actions (new task, new project, toggle list/board), navigation to every page, and live search over projects, tasks and ideas (2+ characters).

Many at once

Bulk actions

Select rows with the checkboxes (Shift-click selects a range) and the action bar appears: set status, priority or assignees, or archive, restore or delete. Each task is authorised on its own; the result reports which succeeded. Up to 200 tasks per request (POST /api/v1/tasks/bulk, MCP bulk_update_tasks).

Lifecycle

Archive, restore and delete

  • Archive hides a project or task from lists, boards and search but keeps everything. Archived items are on Archive; restore them there.
  • Administrators can auto-archive projects that have been Done for a number of days (POST /projects/auto-archive).
  • Delete is permanent and removes children, comments, time entries, files and sketches with the item.
Danger

Deleting a project cannot be undone. Prefer archiving; only the owner or an administrator can delete.
