Chapter 9

MCP server

Monolith speaks the Model Context Protocol, so Claude and other assistants can plan projects, update tasks, log time, comment and draw sketches for you. Every tool is typed, runs as the owner of a personal token, and goes through exactly the same permission checks and side effects as the web app.

Endpoint /mcp/sse (SSE) or stdioAuth personal token, Authorization: Bearer mono_mcp_…Code backend/app/mcp/
Model

How MCP acts

As you, never as a superuser

A token belongs to one person. Tools see exactly what that person sees and may do exactly what their project roles allow (2.4). There is no shared server key.

Same code path as the UI

Each tool calls the REST handler behind the matching screen. Validation, status roll-up, automations, notifications, webhooks and audit behave identically; the bridge is app/mcp/context.py.

Checked on every call

The token is resolved again for each tool call, so revoking it, expiring it or deactivating the account takes effect on the next request, even inside an open session.

Errors are errors

Refusals come back with isError: true and a readable reason such as Permission denied: … or Invalid input: name: Field required. Results are structured JSON.

Credentials

Personal tokens

  1. Open Settings › MCP access.
  2. Name the token after the assistant or machine (“Claude Code on laptop”), choose an expiry (30 days, 90 days, 1 year or never) and Create token.
  3. Copy it now. It is shown once; only a SHA-256 hash is stored. The list shows each token's prefix, creation, last use and expiry.
  4. Revoke a token you no longer use. Revoked and expired tokens stay listed for the record.

Without the UI (for automation), mint a token inside the backend container; only the token is printed:

export MONOLITH_MCP_TOKEN=$(podman exec monolith_backend python -m app.scripts.mint_mcp_token --email you@example.com --name "CI bot" --expires-in-days 30)

REST: GET / POST /api/v1/users/me/mcp-tokens, DELETE /api/v1/users/me/mcp-tokens/{id}.

Danger

A token is as powerful as your account in every project you can reach. Keep it out of repositories and shared configuration, give each client its own, and prefer an expiry.

Clients

Connect a client

Claude Code

claude mcp add --transport sse monolith http://localhost:8080/mcp/sse --header "Authorization: Bearer $MONOLITH_MCP_TOKEN"

Claude Desktop and other stdio-only clients

Bridge SSE with mcp-remote in claude_desktop_config.json:

{
  "mcpServers": {
    "monolith": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:8080/mcp/sse", "--header", "Authorization: Bearer mono_mcp_…"]
    }
  }
}

stdio on the server host

podman exec -i -e MONOLITH_MCP_TOKEN=mono_mcp_… monolith_backend python mcp_server.py

The process refuses to start without a valid token. Settings › MCP access › Connect an assistant shows all three snippets filled in with your address.

Host check

DNS-rebinding protection accepts only the host of APP_BASE_URL, localhost and 127.0.0.1 (any port). Reaching the server under another name, such as a LAN address or a reverse-proxy domain, needs MCP_ALLOWED_HOSTS=mcp.example.com,10.0.0.5. Turn the endpoint off with MCP_ENABLED=false.

Prompts

PromptPurposeArguments
plan_projectTurn a goal into a fully specified Monolith project (phases, tasks, estimates, dependencies).goal, start_date, deadline, budget

Not exposed

Signing in, registration, password reset and e-mail verification; binary uploads and file downloads (use the web app or REST); calendar-feed tokens; the e-mail outbox. These either need a browser, carry secrets, or are operator tasks.

Example

The sample project

scripts/mcp_sample_project.py builds a production-grade example entirely through MCP tool calls, from the payload in scripts/sample_project.json:

PartContents
Project“Helios — Customer Data Platform Migration”: full description with success criteria, In Progress, High priority, start 2026-09-01, planned finish 2027-03-12, hard deadline 2027-03-31, budget €480,000 planned versus €312,500 actual, risk 3 × 4, tags.
TaxonomyProject-scoped topics (Ingestion, Data quality, Security & privacy, Analytics) and work types (Engineering, Analysis, Change management).
Custom fieldsAllocation % (number) for resource allocation per task, Cost centre (text), Work package (select WP1–WP5).
Tasks5 phases with 22 tasks beneath them: PERT estimates, a forward schedule, mixed statuses, three gate milestones with deadlines, budgets and actual costs, risk on the critical items, checklists, a weekly recurring status task, assignees.
DependenciesFinish-to-start and start-to-start links with positive and negative lag.
CollaborationLogged time entries, threaded comments, a voted idea, an architecture sketch drawn from generated Excalidraw elements (with a server-rendered preview) and a runbook note in the File Hub.
PeopleExisting active users become members (editors, and a viewer when there are enough) and assignees. The script never creates accounts; pass --member email:role to choose them.
 
pip install "mcp<2"
export MONOLITH_MCP_TOKEN=mono_mcp_…
python scripts/mcp_sample_project.py --replace                  # SSE at http://localhost:8080/mcp/sse
python scripts/mcp_sample_project.py --stdio --replace          # podman exec … python mcp_server.py
python scripts/mcp_sample_project.py --member ana@example.com:editor --member bo@example.com:viewer

It prints the critical path, statistics and the project's health and deadline status at the end. --replace deletes a previous run first, so it is safe to repeat.

Practice

Working with an assistant

  • Start with whoami and list_projects; the server's instructions tell the assistant the statuses, priorities and date format.
  • The plan_project prompt walks an assistant through a complete plan (phases, estimates, dependencies, a critical-path check against the deadline); weekly_status_report drafts a report from live data.
  • Give viewers' tokens to read-only assistants: their writes fail with Permission denied.
  • Changes an assistant makes to a sketch appear immediately for people who have it open (5.3).
