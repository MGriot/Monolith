Chapter 5

Collaboration

Talking about the work next to the work: threaded comments, an ideas pipeline, sketches that several people draw on at once, a file hub that shows what is inside each file, and notifications that reach people where they are.

Discussion

Comments

Projects (Activity tab), tasks (editor) and ideas each have a discussion. Messages are Markdown with links and images: attach a file, or pick an image from the project's Gallery, which includes every sketch preview. Comments can be threaded (parent_id), which the API and MCP expose; replies come back nested. Authors edit and delete their own comments, project admins any. Editors and above can comment; viewers read.

Pipeline

Ideas Hub

  1. Propose an idea on a project (optionally about one task) from Ideas or the project's Ideas tab.
  2. Vote up or down; voting again the same way removes your vote. Ideas sort by score.
  3. Decide: project admins set Approved or Rejected.
  4. Promote to a task in the project, or to a new project of its own. The idea becomes Converted and links to the result.
Real time

Sketches (Excalidraw)

Sketches are Excalidraw whiteboards that belong to a project and optionally a task. Create one from File Hub › New › Sketch, or from a task's attachments; open it full-screen from the File Hub's Sketches view.

Drawing together

As soon as a sketch has been saved once, everyone who opens it joins its live room:

  • Edits appear for the others within a fraction of a second. Changes merge element by element with Excalidraw's own rule (newer version wins), so two people editing different shapes never overwrite each other.
  • Everyone's pointer and name show in their own colour; the toolbar chip reads Live · 2 others. The collaborators are the real signed-in members, nobody else.
  • The room saves automatically a few seconds after the last change and when the last person leaves. Save is still there to rename the sketch or force a save.
  • Viewers follow along in view-only mode (View only badge); the server refuses edits from them. Roles are re-checked every few seconds: someone demoted to viewer drops to view-only, someone removed from the project is disconnected.
  • If the connection drops, the chip shows Offline and the editor reconnects with backoff, then merges what changed meanwhile.

Sharing

Share (or the live-collaboration button in the canvas) opens the share dialog:

  • a link for project members to copy,
  • Here now: who is connected, with their colour and role,
  • the project's members and roles; project admins add any existing user as viewer or editor, or change and remove roles, right there.
Note

Access to a sketch is access to its project: there are no separate sketch permissions to forget. Adding someone as a viewer lets them watch; editor lets them draw.

Previews

Every sketch has a thumbnail in the File Hub, in task attachments and in the comment image picker. The editor exports a PNG when you save, and the leader of a live room (the editor who joined first) refreshes it after ten quiet seconds. Sketches written without a browser (MCP, imports) get an SVG rendered by the server. Previews are files under /uploads/previews/; whiteboard lists return only their URL, never the scene.

Export

From a task, Export to Task attaches the sketch as a PNG.

Files

File Hub

Each project (and each task) has a File Hub: nested folders, uploaded files up to MAX_UPLOAD_MB (50 MB by default), Markdown notes and the project's sketches.

  • Upload by dropping files anywhere on the hub, or with New › Upload; an upload tray shows progress and retries.
  • Organise: drag files and folders onto folders or breadcrumbs, rename inline, tag files with topics, switch grid and list.
  • Find: the side navigation filters by kind (images, PDFs, documents, spreadsheets, presentations, notes, sketch files, archives, media).
  • Notes are written and previewed as Markdown in place.

Careful

Files under /uploads are served to anyone who has the URL; names are random UUIDs, so they cannot be guessed. Uploads that could execute in a browser (HTML, JS, SVGZ…) are refused, and SVG is served as a download with a sandbox policy.

Inbox

Notifications

The bell shows unread notifications in real time over a websocket (assignments, automation messages and deadline reminders). Notifications lists them all with filters by type and read state; mark one or all as read, or mark unread again.
