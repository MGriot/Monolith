Chapter 10

API reference

Everything the web app does goes through this API. The interactive version with request forms and full schemas is at /api/docs (Swagger) and /api/redoc on a running stack; the machine-readable spec is /api/openapi.json.

Basics

Conventions

TopicRule
Base URL{APP_BASE_URL}/api/v1
AuthenticationPOST /login/access-token (form fields username, password) returns a bearer JWT valid for ACCESS_TOKEN_EXPIRE_MINUTES; send Authorization: Bearer <token>. Tokens carry no roles: permissions are read from the database on every request.
Errors400 invalid request, 401 not signed in, 403 missing role, 404 not found or not visible, 409 conflict, 413 too large, 422 validation (FastAPI detail list), 429 throttled.
Pagingskip and limit (max 500 unless noted).
DatesISO 8601; stored as naive UTC.
Partial updatesPUT bodies change only the keys they contain.
 
TOKEN=$(curl -s -d "username=you@example.com" -d "password=$PW" http://localhost:8080/api/v1/login/access-token | jq -r .access_token)
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/v1/projects/

POST/api/v1/tasks/bulkBulk Update Tasks

Apply one patch (status / priority / assignees) or one action (archive / restore / delete) to many tasks. Every id is authorized on its own with `require_task_access(write=True)` in a first pass; ids that fail (403/404) are reported in `results` and left untouched. The permitted ones are applied in ONE transaction, each inside a SAVEPOINT so a task that cannot take the change (e.g. 400 validation) is reported without undoing the others.

Body application/json BulkTaskRequest: ids, patch, action

Whiteboard rooms · /api/v1/whiteboards/{id}/ws

Requires read access to the sketch's project; sending edits requires editor. Elements are Excalidraw elements; the server keeps the merged scene and saves it.

DirectionTypePayload
→auth{"token"}, first message
←initself (your peer entry), role, elements, files, peers, leader
→ ←scene_update{"elements": [changed elements]}; merged by version, relayed to the others. Refused for viewers with an error.
→ ←files{"files": {id: BinaryFileData}} for images on the canvas
→ ←pointer{"pointer": {"x", "y", "tool": "pointer"|"laser"}, "button": "up"|"down"}; relayed with the sender's peer id, about 30 per second at most
←peerseveryone in the room (id, user_id, name, role, color) and the preview leader
←role{"role"}: your project role changed while connected (re-checked every few seconds); a removed member gets an error and the socket closes with 1008
←scene_replacethe whole scene, after a REST or MCP write replaced it
→ / ←ping / pongkeep-alive
←error{"message"}

Merge rule: an incoming element replaces the stored one when its version is higher, or equal with a lower versionNonce. Rooms live in the backend process; the scene is saved 3 seconds after the last change and when the room empties.
