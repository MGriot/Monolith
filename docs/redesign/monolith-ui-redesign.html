Monolith UI Redesign

One layout system for dialogs, the Dashboard, Metadata, Settings and the File Hub. The plan builds on what already works in the codebase (the sized dialog primitive, the HSL tokens and the two-pane task editor) and doesn't rewrite it.

Frontend React 19 · Tailwind 3 · Radix · dnd-kit Source docs/ui-redesign-plan.md Status Not started
DialogsOne dialog standard. Project editor matches the task editor. DashboardSummary first, fewer cards, compact empty states. MetadataNo tabs. Topics and work types side by side, edited inline. SettingsSection nav, settings rows, one scroll. File HubDrag-and-drop file manager with previews.

Phase P0

Design foundation

Every later phase depends on this. It adds tokens and primitives without changing pages, so it can ship first with no visual regressions.

Semantic color tokens

Add these to index.css next to the existing --subtle and --fg-faint, and map them in tailwind.config.js the same way. Then rebuild STATUS_COLORS and PRIORITY_COLORS in constants/colors.ts on top of them, so chips, Kanban, Gantt and the Dashboard read one source.

info / info-softIn progress, drop targets
success / -softDone, under budget
warning / -softOn hold, medium risk
danger / -softOverdue, delete, over capacity
review / -softReview status
surface / sunkenCards and dialogs / page, rails, footers

Swatches follow your light or dark theme. Each soft background is about 10% of its hue in dark mode.

Type scale

These are the only sizes allowed. Nothing goes below 11px, font-black is retired, and uppercase only appears through the Eyebrow component. A lint rule flags new font-black and text-[8–10px].

Spacing, radius, elevation

  • 4px grid. Page gutter px-4 md:px-6 lg:px-8, card padding p-5.
  • gap-6 between page sections, gap-4 inside grids.
  • Cards and dialogs rounded-xl, controls rounded-md, chips rounded-full.
  • Cards get a border and no shadow. Popovers shadow-lg, dialogs shadow-2xl.
  • Clickable cards show hover through the border color only.

One scroll container per surface

  • Pages scroll only in the layout's <main>. Settings and Metadata lose their extra overflow-auto wrappers.
  • Dialogs scroll only in DialogBody, or in the editor panes. Footers never sit inside the body.
  • Long lists on a page use "Show all (n)", not an inner scrollbar.
  • Exceptions: Gantt, Kanban columns and File Hub panes, which are workspaces.

Checks for every phase

  • npm run typecheck, npm run lint and npm test in frontend/; pytest in backend/ for P4a.
  • Screenshots of each changed page in light and dark at 375, 768, 1440 and 2000px, replacing the outdated ones in docs/img/.
  • Keyboard pass: every dialog opens, submits with Ctrl+Enter, closes with Esc and traps focus.
  • Contrast of at least 4.5:1 for text. Check status chips in dark mode first, since the soft backgrounds are the risk.
Reference

Styling guidelines

Do

  • One primary button per view
  • Sentence-case labels through Field
  • Icons at h-4 w-4, muted, one per header
  • tabular-nums on every number that lines up
  • Skeletons, not spinners, for panels that load with the page
  • Status colors from tokens: bg-info-soft text-info

Don't

  • Nest cards inside cards
  • Uppercase anything outside Eyebrow
  • Use text smaller than 11px or font-black
  • Put shadows on cards
  • Add inner scrollbars to document pages
  • Use raw slate-* or blue-50 classes where a token exists (24 slate-* uses remain)
